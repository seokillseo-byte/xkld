# DuHocHaNoi — Public Content & Launch QA

## 1. Brand and legal facts
- [ ] Confirm official domain and canonical host (www or non-www).
- [ ] Verify legal entity name, business address, registration and applicable licences/scope.
- [ ] Verify hotline, email, working hours, map/address and responsible team.
- [ ] Confirm each named school, employer, partner and programme in writing.
- [ ] Remove all sample contact details before launch.

## 2. Programme content
For each study/work programme, record:
- [ ] Country, institution/employer, programme type and target audience.
- [ ] Eligibility, language, education/experience, health or other requirements.
- [ ] Application steps, timeline and current intake/availability.
- [ ] Full itemised fees, payment milestones, refund/cancellation terms and receipts.
- [ ] Contract, pay/deductions/benefits where applicable, insurance and complaint route.
- [ ] Primary source URL, source owner, last verified date and reviewer.
- [ ] Clear caveat that outcomes are not guaranteed; avoid unsupported visa/job/salary promises.

## 3. SEO and publishing
- [ ] One descriptive title and unique meta description per indexable page.
- [ ] Confirm domain before adding absolute canonical, Open Graph URL and sitemap.
- [ ] Generate XML sitemap only for canonical, indexable URLs that return 200.
- [ ] Check internal links, redirects, 404s, heading order and image alternative text.
- [ ] Add structured data only when it accurately represents visible and verified facts.
- [ ] Connect Search Console and analytics with appropriate privacy disclosure.
- [ ] Add named author/reviewer, sources, last-reviewed date and update workflow for advice content.

## 4. Lead form and privacy
- [ ] Replace demo-only submit handler with a validated server endpoint.
- [ ] Define purpose, consent/legal basis, retention, access, deletion and third-party processors.
- [ ] Add rate limiting, bot protection, server-side validation and safe error handling.
- [ ] Keep secrets in environment/secret manager; never commit credentials.
- [ ] Restrict access to leads by role and log access/export/deletion.
- [ ] Test mobile, keyboard use, accessible labels and clear success/failure states.

## 5. Technical release gates
- [ ] Add automated HTML/link checks and tests for the form/API.
- [ ] Check mobile layouts, keyboard navigation, contrast and Core Web Vitals.
- [ ] Confirm backups, monitoring, security headers, HTTPS and environment separation.
- [ ] Do not publish until legal facts and all sample data are replaced and reviewed.
